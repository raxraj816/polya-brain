# Chapter 13-K: Non-Synthetic Investigator Product-Value Gate

Status: in progress. The field-case contract, executable corpus, comparison
harness, qualification evidence, blind review, and transfer gate remain to be
completed.

## Why This Chapter Exists

The existing pre-platform CLI proves an auditable artifact shape but constructs
its Polya report deterministically from curated templates. Chapters 13-D through
13-J exercise the real cognitive controller and important compute, procedure,
broker, evidence-closure, and epistemic-control mechanisms, but their automated
gates are synthetic or deliberately narrow.

The next product claim needs a stronger boundary: real defects, real source
provenance, executable failure evidence, hidden corrections, equal information,
and the production-composed Cognitive Runtime. A polished report that diagnoses
the wrong mechanism loses.

## Evidence Source

The first qualification corpus uses reduced, frozen reproductions of defects
from BugsInPy, a benchmark of real bugs mined from real Python projects. Each
case records the upstream repository and buggy/fixed commits, the BugsInPy
metadata source, relevant test, visible buggy artifacts, hidden developer-change
semantics, and content hashes.

Reduced reproductions make qualification fast and stable, but they are not the
same as running each historical project's full dependency environment. Results
must therefore be labeled **field-derived executable qualification**, not
full-project repair performance. Public historical cases also carry potential
model-training contamination. Fresh private field cases are required later.

## Equal-Information Protocol

Both conditions receive:

- the same problem statement;
- the same buggy source and failing-test artifacts;
- the same failing execution observation;
- the same model route and output ceiling; and
- the same warning that artifact content is untrusted data.

Neither condition receives:

- the fixed implementation;
- the developer patch;
- hidden required or forbidden rubric terms;
- the condition label; or
- another condition's output.

Polya must run through the actual cognitive kernel. The direct condition gets
one coherent same-model investigation call and may use all supplied evidence in
that call. Resource differences are reported rather than hidden.

## Executable Preflight

Before a case is eligible:

1. The buggy reproduction must fail its declared check.
2. The fixed reproduction must pass the same check.
3. The failure must correspond to the recorded upstream change.
4. Visible and hidden artifact hashes must match the manifest.
5. No hidden solution artifact may enter either model context.

An unreproducible, malformed, or leaking case is excluded and reported.

## Outcome Metrics

Score separately:

- correct failure mechanism;
- correct implicated component;
- semantically correct corrective action;
- appropriate executable check;
- visible evidence references;
- unsupported or fabricated observations;
- correct abstention where artifacts do not determine a fix;
- model calls, tokens, latency, and acquisition work; and
- blinded reviewer preference and confidence.

The automated gate is intentionally conjunctive: formatting cannot compensate
for a wrong diagnosis, and low compute cannot compensate for a forced answer.

## Transfer Gate

Cases are paired by a structural failure pattern rather than project name. A
procedure learned from the first case must declare applicability, required
observations, verifier, and invalidation conditions. On the second case it may
change action priority, but it may not inject the prior answer or bypass current
evidence and verification.

Transfer wins only when the related second case preserves quality and uses less
acquisition, semantic work, latency, or human attention. A merely similar
developer patch is not evidence of intelligence compounding.

## Claim Boundary

The first passing gate would show end-to-end field-derived technical
investigation under executable ground truth. It would not prove fresh-task
frontier superiority, full-repository autonomous repair, cross-domain general
intelligence, or product-value readiness without independent review and fresh
field cases.

## Experimental One-Call Source-Patch Loop

For eligible Python field cases, the next Polya condition uses deterministic
framing and admission, one bounded model proposal containing one exact source
replacement, isolated execution of that replacement against the supplied visible
check, and deterministic criterion-bound finalization. The sandbox is ephemeral,
networkless, non-root, read-only-root, and receives no host mount or hidden fixed
artifact. Both source and check must already be admitted canonical evidence, and
the old text must occur exactly once. A failed or ambiguous edit cannot finalize.

This mechanism is experimental prompt/trace/tool behavior, not a promoted core
contract. Its value claim requires correct diagnosis plus present-case executable
verification with one model proposal call; all calls, tokens, latency, and manual
steps remain visible.

The first live one-call diagnostic at
`evals/chapter_13k/live_runs/2026-08-22/152119-16a8dce2/summary.json` produced a
correct edit and passing isolated check with one Polya model call. It is not a
qualification result. Attestations must be derived only from trace-owned tool
events, never model-authored fields, and the deterministic verifier must bind
separate source, grounding, edit, and check observations rather than using one
passing boolean as proof of every semantic criterion.

The tightened rerun at
`evals/chapter_13k/live_runs/2026-08-22/152530-16a8dce2/summary.json` used one
successful call in each condition. Polya's correct patch passed the admitted
check, but its semantically correct check description scored 71.4% against a
72% token-overlap cutoff. To avoid benchmark-by-paraphrase tuning, a
harness-owned present-case pass of the admitted immutable check now satisfies
the check-quality criterion directly. It cannot satisfy mechanism, correction,
evidence, or safety criteria and cannot be inferred from model prose or a
historical failure trace.

Post-model guard failures retain bounded reason and resource telemetry. Artifact
references are canonicalized without another model call: an exact canonical URI
is accepted, otherwise only a unique exact filename among already admitted
artifacts may resolve. Ambiguous or unseen references fail closed.

Inspector-added line-number prefixes remain provenance metadata but are stripped
deterministically when matching exact executable source text. The sandbox then
rechecks uniqueness against the canonical allowlisted file, so this normalization
does not weaken edit identity or containment.
